# Monolith to Microservices

Monolith to Microservices, by Sam Newman, tackles the question most microservices books skip: how do you get there from the system you already have? It is a book about migration, not green-field design.

Newman lays out incremental refactoring patterns for decomposing an existing monolith, starting with the decision of whether to migrate at all. Core techniques include the Strangler Fig pattern for gradually routing traffic away from the monolith, branch by abstraction and parallel run for changing code safely, and a substantial set of patterns for the hardest part — breaking apart the shared database through splitting, replication, and reporting. Case studies throughout ground the advice in real migrations.

The tone is deliberately cautious and pragmatic: services are decomposed along seam lines, data consistency is handled explicitly, and reversibility is valued. If your team owns a growing monolith and is weighing the jump, this is the guide to read first. It won't tell you to migrate — it will show you how to do it without breaking everything.
